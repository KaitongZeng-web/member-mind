# 独立使用与连接状态说明（v0.4.2）

member-service 的核心能力**完全本地、零外部依赖**：导入会员表、按条件筛选、生成简报、
结构化纪要并生成行动计划，都不需要任何外部工具或联网。外部企业检索(QCC等)是**可选增强**，
没有也能完整走通主线。

## 三种使用方式

1. **完整链（推荐）**：导入会员 CSV/XLSX → 按条件筛选 → 生成拜访简报 → 粘贴纪要结构化并核对 → 生成行动计划。
2. **从纪要单独开始**：即使没有会员表，也可以直接粘贴原始纪要 → 结构化 → 人员核对 → 生成行动计划
   （此时 `entity_id` 可空，任务关联到该次拜访）。
3. **只用筛选/简报**：已有会员表时，按条件筛出目标并生成一页简报即可。

## 跨会话恢复

- 所有状态在 `--workdir/index.json`，人类可读索引在 `--workdir/README.md`。
- 新会话只需指向同一个 `--workdir`（或设置 `MEMBER_WORKDIR`），即可接着看主体、结果、任务，
  **不依赖聊天记录**。
- 结果按生成时的 `data_version` 判定是否因数据更新而过期（README 中标注“过期”）。
- `index` 子命令随时打印当前摘要。

## 连接状态（外部检索可选）

| 状态 | 含义 | 影响 |
|---|---|---|
| 本地（无外部工具） | 未配置/未发现 QCC 等连接器 | 主线全部可用；外部找客户/补信息暂不可用，标记 `no_tool` |
| unauthorized | 发现工具但未授权 | 需在宿主侧授权；脚本不伪造授权 |
| planned | 有工具但本轮不代发调用 | 只整理意图，不返回真实结果 |
| partial | 候选回包为部分结果 | 标注可能遗漏，不视为全量 |

**当前本环境未实测真实 QCC 连接**，属实现边界：`mcp-search` 在无工具/未授权时返回
`no_tool`/`unauthorized`，`mcp-ingest` 只用 mock 回包演示归一化（全程 `is_mock=true`）。
不据此声称已真实查询；在授权范围内可改用真实工具/schema 查询并导入回执。

## 已验证 / 未验证边界（如实说明）

**已在本机验证（Python 3.9.6，仅标准库）：**
- CSV 与 XLSX（标准库 OOXML 读取：多 sheet、公式缓存值、合并单元格、错误值）导入。
- 字段别名映射、冲突/缺失/重复/异常报告；未知→null+原因；稳定主体身份与幂等重导入。
- 三值逻辑筛选（缺失不因 NOT 变真；硬排除优先；eligible/excluded/needs_review 分流）。
- 纪要结构化（幻觉引用标记、内嵌指令只标记不执行、引用行号定位）、核对、计划、任务更新。
- CSV 导出公式注入防护；路径越界拒绝；原子写。
- CLI 退出码与返回信封。

**未验证 / 需宿主确认（不夸大）：**
- **WorkBuddy 的安装与运行未验证**：不保证“开箱即用”，需按 SKILL.md 由宿主代调用脚本。
- 自然语言→条件树、自然语言→纪要结构化，由**宿主模型**完成；脚本不解析自然语言，
  不假装具备通用 NL 能力。
- 真实 QCC/腾讯检索未执行；相关结论仅来自接入要点记录，非真实查询结果。
- 具体宿主的权限、工具发现、授权流程以实际环境为准。

## 普通用户无需终端

正常用户只做三件事：**上传/粘贴文件 → 查看生成的 MD/CSV 结果 → 继续或确认**。
所有 `scripts/ms_cli.py` 调用都由宿主在内部完成，用户不手写 JSON、不进命令行。
