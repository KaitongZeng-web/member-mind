## 聊天导入（2026-10-31 新增）

服务概览点击“开始导入”或“打开聊天导入”，进入自然语言资料助理；操作员界面的CSV上传入口已移除，统一使用聊天导入。

1. 在“连接与模型”填写自己的 DeepSeek API Key 并保存。默认模型为 `deepseek-flash`，可按账号可用模型修改名称。
2. 六个企查查 MCP 端点已预置。企查查 API Key 可在同一处填写，或通过服务端 `QCC_API_KEY` 环境变量配置。不要把实际密钥写进 MCP 配置参数或源码。
3. 输入企业名称、简称、信用代码或自然语言业务需求。程序发现真实工具目录，DeepSeek按工具Schema组织查询参数，后端校验后调用。名称查询最多返回5家实际匹配企业，按企查查返回顺序展示并补查对应公开资料；业务需求查询按上文语义检索流程处理。每轮合计最多18次工具查询，不自动重试结果不明的调用，不足5家不补造。
4. 查看助理回复、推荐依据、来源说明及待审字段。每个采用的公开字段都有可匹配的来源原文，行业与地区接受来源中的实际业务值，不再局限于演示字典。企业名称、信用代码和经营状态可来自同一条企查查搜索记录，详细资料来自对应主体的工商登记或企业简介查询。多候选直接生成待选卡片，不要求先继续对话才能勾选；每家的身份和字段分别校验，禁止串用其他企业的信用代码或状态。操作员界面将技术参数与原始JSON转换为业务说明。

## 现在是什么

在V2工作台基础上保留现有业务页面，增加Python/FastAPI后端与SQLite数据库。企业、证据、问题、批次、成果、变更、行动、纪要、任务及日志写入服务器数据库；刷新页面和重启服务后保留。业务不再依赖浏览器localStorage，也没有将整个浏览器状态直接PUT进数据库的接口。

MCP提供通用配置界面与六类企查查预置端点；保存配置不连接第三方。聊天发送消息后才发现并按需查询。通用MCP页面仍支持手动发现、白名单与确认调用。本机示例仅用于协议联调。

## 快速使用（Windows）

1. 解压完整项目，电脑已有Python 3.11或更新版本。
2. 双击 **启动网站.cmd**，或在项目目录执行 `python start.py`。
3. 保持启动窗口运行，在浏览器打开 **http://127.0.0.1:8877**。
4. 关闭服务用启动窗口Ctrl+C；数据仍保存在 `data/workspace.sqlite3`。

本包附Windows x64 / CPython 3.13依赖wheel，可在这一环境离线完成安装。其他Python版本或Linux首次安装需要联网，或另备匹配平台依赖；安装完成后模拟业务运行无需网络。不能再双击HTML运行，因为此版依赖Python API。


| 功能 | Python端职责 | SQLite保存 |

| 简报与盘活 | 事实来源、模板简报、硬性准入及优先级 | 简报、盘活成果 |
| 活动与模拟通知 | 活动准入、名单验证、确认、查重、状态与回执 | 通知批次及逐企业记录 |

所有业务写入用SQLite事务；`expected_revision`防止多个页面覆盖；`request_id`用于同一业务请求的幂等处理，参数不一致时拒绝。导入确认只接受服务器保存的预检编号；筛选结果、分数、通知准入和任务状态均在Python中计算或校验，不接受前端伪造结论。

数据仍为匿名模拟，规则参考日期2026-10-31；无正式会员分级规则的字段保留待确认。文案仍为规则模板，不冒充大模型。通知和批次功能已移除，任务完成不自动续费。

## MCP配置界面

侧栏“**MCP接口配置**”：

- 服务器名称、Streamable HTTP或stdio。
- HTTP端点URL、Bearer鉴权环境变量名。
- stdio程序和JSON参数数组。
- 超时（1—120秒）、允许调用的工具名列表、启用状态。
- 保存后不自动连接；需要手动点击“测试连接与发现工具”。
- 调用工具前填写JSON参数、预览并确认，服务器再次检查白名单。
- 记录pending/success/failed/unknown，调用不明不自动重试。
- MCP输出只作返回资料，不自动当作企业事实或更新画像。

HTTP示例（在页面中填写）：

```
传输：streamable_http
URL：https://your-server.example/mcp
鉴权环境变量名：FUTURE_MCP_TOKEN
允许工具：["your_read_tool"]
启用：按实际接入条件选择
```

启动前在本机PowerShell设置真实密钥：

```powershell
$env:FUTURE_MCP_TOKEN = '你的实际密钥'
python start.py
```

网页和SQLite配置只保存环境变量名，不保存实际Bearer密钥；更改环境变量后重启Python进程。`.env.example`仅是变量说明，不自动加载.env。

stdio支持`@python`代表当前虚拟环境Python，`@project/`代表项目目录。例如程序`@python`，参数`["@project/sample_mcp_server.py"]`。stdio会运行配置的本机程序，使用参数列表而非shell；只配置你实际信任的服务程序。

可选本地只读示例：点击“填入本地只读联调示例”，手动勾启用、保存、测试连接；工具为`get_demo_profile`，调用参数`{"entity_id":"企业 A"}`。也可运行 `python sample_mcp_server.py --transport streamable-http`，连接 `http://127.0.0.1:8878/mcp`。示例返回始终标注模拟。

已支持：stdio、Streamable HTTP、环境变量Bearer。未实现：OAuth交互授权、旧版SSE、资源/提示词UI、自动模型选工具、腾讯平台账号集成。第三方服务器的认证与工具Schema以后按实际定义整合。

## 数据库与备份

数据库默认 `data/workspace.sqlite3`，启用WAL。每类对象独立SQL表，以对象ID及企业关联字段索引，payload保留原业务结构。SQLite中另存修订元数据、幂等请求、服务端导入预检和MCP配置/调用。

- 网页“导出整个工作空间”下载业务JSON，不含MCP密钥；它不是数据库完整副本。
- 完整在线SQLite备份：`python backup_db.py backup-20261031.sqlite3`，使用SQLite Backup API，无需直接复制正在写入的WAL文件。
- 恢复数据库：停止服务，备份现有文件，将完整备份替换为配置的DB路径，再启动。勿在运行中替换DB。
- 旧V2迁移：先从旧网页导出工作空间JSON，再停止旧服务，执行 `python import_v2.py 路径/旧工作空间.json`。新数据库有修改记录时，先备份，再加`--replace`明确替换。迁移不连接旧网页、不自动读取浏览器存储。

压缩包提供新环境初始化资料，不包含本机联调过程的数据库或真实密钥；第一次启动自动创建36家模拟数据的数据库。安装在本机的项目当前数据库则保留了实际网页联调记录。

不要把stdio进程配置、MCP调用入口或无账号工作空间直接向无关公网用户开放。该限制源于当前已实现的本机共享模式，不是生产权限系统。

## 项目结构

```
backend/domain.py        Python业务规则
backend/service.py       业务命令及状态转换
backend/store.py         SQLite事务与对象存储
backend/mcp_gateway.py   MCP配置及客户端
backend/app.py           FastAPI路由与静态前端
frontend/                现有工作台页面及API适配
config/seed.json         匿名初始化样例、字典
sample_mcp_server.py     可选只读联调服务器
run.py / start.py        服务与依赖启动
backup_db.py             完整数据库备份
import_v2.py             旧版JSON迁移
wheels/                  Windows CPython3.13离线依赖
```

技术依据：MCP官方Python SDK v1维护分支（https://github.com/modelcontextprotocol/python-sdk/tree/v1.x）及客户端说明（https://github.com/modelcontextprotocol/python-sdk/blob/v1.x/docs/client.md）。项目固定mcp==1.30.0；支持的两类传输由官方SDK负责协议生命周期。
